04 · 踩过的坑

我们踩过哪些坑？

两个项目、两份复盘、半年时间 —— 抽象出来其实就四类。
PIT 01 · 最贵
底层数据基础
不扎实
口径没版本、底表关联键是空的、同名不同物、地名没有唯一编码。AI 答错的那些题，追到底全是这一件事。
口径梳理花了 4 周 —— 自研还是买平台，都省不掉。
PIT 02 · 最隐蔽
把判断权
交给了模型
让模型自由写 SQL、自己判断地名层级、自己决定报告结构。
结果是：答案语气笃定，前提是错的。
PIT 03 · 最危险
声明了保护
不等于有保护
权限隔离改了三次才真正隔住；「只读挂载」做完才发现凭据没做读写分离。
保护要一路验到最底层。
PIT 04 · 最耗时
先建可观测性
再谈优化
固定套路「盲修 → 修不动 → 加日志 → 找到根因」，在六个模块上重复了六遍。
看不见的时间，才是真正的成本。
四类坑看着不相干。但排在一起会发现 ——
每一个都是「某处该由代码决定的事，被交给了模型、或者运气」。
所以我们做的不是一个更聪明的系统，而是一个刻意让 AI 少做判断的系统 ——
凡是关系到准确性的环节，全部换成可复现的代码。
AI 问数复盘 · 一条主线  /  「AI 不要完全依赖 AI，要用 Code + AI 结合的方式」
05 · NEW VOCABULARY · 新词层出不穷

这些 新词，背后是什么？

每一个词背后，都是一次能力跃迁 · 悬停看解释 · 绿色 = 最近一个月
Jev 前 OpenAI 研究员做的「System One 模型」——不生成文字，只输出结构化判断：选项、评分、0-1 概率。结构上无幻觉。
Agentic AI 2026 云栖大会的核心锚点。从「能回答」到「能自己把活干完」。
Harness 由平台为模型配备工具、沙箱与执行循环，让 AI 真正动手。我们的 Agent 平台就是照这个思路建的。
RLCD Reinforcement Learning for Calibrated Decisions —— Jev 的训练方法，优化目标是「诚实的概率」，而不是 RLHF 的「人类偏好」。
Vibe Coding 凭「感觉」编程——描述意图给 AI，不再写每一行代码。我们 38 个应用基本都是这么来的。
团队智能体 有独立身份、权限和记忆，能像同事一样加入群聊——AI 的服务对象从个人扩展到整个团队。
MCP Model Context Protocol —— 让大模型连接外部工具与数据的标准协议。
Skill 可注册、可分发、可版本化的能力包。新能力 = 加一个技能，不改架构。
Guardrails 护栏——内容双向审查管「说了什么」，工具调用拦截管「做了什么」。先审后执行，不是事后补审。
World Model 世界模型——让 AI 建立对物理与因果的内部模拟，而不只是预测下一个词。云栖有专场。
A2A Agent to Agent —— 智能体之间互相调用与协作的协议。
Context Engineering 上下文工程——比提示词工程更上一层：决定往有限的上下文里放什么、不放什么。
Temporal KG 时序知识图谱——给 Agent 一张可查询、可追溯的记忆，而不是把什么都塞进上下文。
龙虾 · OpenClaw 红色龙虾图标的开源 Agent，GitHub star 破 25 万，"养龙虾"成为全网热梗——但也带出了「越自主 = 越有用 = 越危险」的龙虾悖论。
Test-time Compute 推理时算力——让模型「多想一会儿」，用算力换更好答案。
Token Foundry 把「机器思考」当成可规模化生产的商品来经营。吴泳铭：未来机器思考总量将是人类的 1000 倍。
韬τ 定律 大模型规模 vs 性能的指数级关系——模型越大越聪明，但代价指数级上升。
CoT · 思维链 Chain-of-Thought——让模型「想给你看」再回答，推理质量显著提升。
RIS 待补充释义。
